PayFreo is a merchant-hosted crypto payment Core in development. It is being built to help applications verify supported token payments while the merchant keeps control of the server, data, RPC provider, and receiving wallet.

The principles

Control belongs with the operator.

Each decision in the first release starts with a clear trust boundary and a narrow scope.

01 /
⌂

Merchant-hosted

The merchant runs the Core, chooses the RPC provider, and owns the database and receiving addresses.

02 /
↘

Receive-only

The initial design has no withdrawals, sweeping, escrow, or merchant signing keys inside Core.

03 /
◎

Evidence before status

Future settlement must match an invoice to a unique address and verified on-chain transfer evidence.

Built in stages

Know what exists.
Know what comes next.

The repository separates working code from design decisions. Payment claims wait for deterministic tests and review.

Start locally

A foundation you can inspect.

Run the current service on your machine. The endpoints report process and database readiness; they do not accept payments.

Full setup and limitations ↗
payfreo / local setup 
# Node.js 24 or supported 22.x · pnpm 11.10.0
$ cp .env.example .env
$ pnpm install --frozen-lockfile
$ pnpm --filter @payfreo/core db:generate
$ pnpm db:migrate && pnpm build
$ pnpm --filter @payfreo/core start:local
!

Security & limitations

Pre-alpha means pre-alpha.

There is no payment engine, independent audit, or production release today. Do not use real funds. A compromised frontend or RPC can still mislead a user; self-hosting does not remove financial risk.
