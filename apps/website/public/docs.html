Developer notes / foundation

Build from what exists.

The current repository contains a local NestJS Core foundation. These notes describe what you can run today and where the payment design stands.

Pre-alpha · Local and testnet development only

01 / REQUIREMENTS

What you need

Use Node.js 24 LTS for primary development. Node.js 22.13.0 or newer on the 22.x line is the compatibility target. The repository pins pnpm 11.10.0. A local SQLite file is enough for the foundation; no RPC provider or wallet key is needed.

Clone the public repository and run these commands from its root. Configuration stays in a local, Git-ignored .env file.

02 / LOCAL SETUP

Run the Core foundation

Terminal · repository root
cp .env.example .env
pnpm install --frozen-lockfile
pnpm --filter @payfreo/core db:generate
pnpm db:migrate
pnpm build
pnpm --filter @payfreo/core start:local

The service binds to 127.0.0.1:3000 by default. For a container-based local run, use docker compose up --build; Compose persists the SQLite database in a named volume.

Run pnpm format:check, pnpm lint, pnpm typecheck, and pnpm test before contributing.

03 / CURRENT HTTP SURFACE

Health, and only health

GET /health/live

Returns 200 when the process responds. It does not check storage or payment capability.

GET /health/ready

Returns 200 after migrations have completed and the Core table is queryable; otherwise 503.

Invoice creation, transaction submission, payment status, authentication, and webhooks are not implemented. A health response must never be treated as a payment confirmation.

04 / DESIGN RECORDS

Why the layers look this way

The health controller handles HTTP, its service owns readiness behavior, and the database module exposes a narrow readiness capability. Future payment modules will need their own services, persistence adapters, and tests.

05 / IMPORTANT LIMITS

Keep real funds out.

PayFreo has not implemented payment verification and has no independent security audit or production release. The future receive-only Core will never need merchant private keys. The merchant must provision distinct public receiving addresses outside PayFreo.

Read the draft threat model and security policy before evaluating the project.
